# Dépendances et chaîne d'outillage

Les versions directes sont centralisées dans `Directory.Packages.props`; les résolutions transitives sont figées dans les fichiers `packages.lock.json`. Le fichier `eng/dependency-policy.json` conserve la date et la source de la revue manuelle des versions sensibles. `.github/dependabot.yml` configure des propositions hebdomadaires pour le plancher du SDK .NET (`global.json`) et les paquets NuGet : dix propositions NuGet ouvertes au maximum, mises à jour mineures et correctives regroupées. Les trois paquets Roslyn explicitement exclus suivent le plancher du SDK et changent avec lui pour préserver la compatibilité des analyseurs. Cette configuration ne prouve ni la création effective d'une proposition ni sa fusion ; les changements restent soumis à revue et aux vérifications du dépôt.

## Décisions vérifiées le 11 novembre 2026

- les packages ASP.NET Core et `Microsoft.Extensions.Localization` sont en `11.0.0` (.NET 11, publié le 10 novembre 2026) et `bunit` en `2.15.2`, dernières versions stables publiées par NuGet.org. Le paquet vise `net10.0` et `net11.0` (décision de l'utilisateur du 2026-11-11, `net9.0` abandonné) : `Directory.Packages.props` déclare pour `Microsoft.AspNetCore.Components.Web` et `Microsoft.Extensions.Localization` une ligne `Condition="'$(TargetFramework)' == 'net10.0'"` en `10.0.15` (dernier correctif stable de la ligne 10.0 sur NuGet.org) et une ligne `!= 'net10.0'` en `11.0.0` ; `eng/dependency-policy.json` relève la ligne `net10.0` sous `frameworkVersions` (statut `latest-stable-patch`), et `eng/Test-DependencyPolicy.ps1` refuse toute autre forme de condition, contrôle les deux lignes et le verrou de la bibliothèque cible par cible. La suite `tests/OmniEurope.Blazor.Tests` et l'outil `eng/OmniEurope.PublicApiGuard` visent aussi les deux cibles ; tous les autres projets (vitrine, hôtes de fumée, analyseurs de dépôt, tests de l'API et de l'analyseur) restent en `net11.0`. Sur `net10.0`, `bunit` `2.15.2` apporte en transitif `Microsoft.AspNetCore.Components.WebAssembly` `10.0.13`, son plancher pour cette cible.
- la bibliothèque a trois dépendances d'exécution, déclarées dans `src/OmniEurope.Blazor/OmniEurope.Blazor.csproj` : `Microsoft.AspNetCore.Components.Web`, `Microsoft.Extensions.Localization` et `HtmlSanitizer` (`11.0.26`, dernière version stable au relevé de `eng/dependency-policy.json`), qui assainit le HTML d'`OmniHtmlEditor` par liste blanche et apporte AngleSharp en transitif.
- la chaîne de tests tourne sur Microsoft.Testing.Platform, déclaré par le bloc `test` de `global.json`. `xunit.v3` `4.0.3` embarque son propre exécuteur, donc ni `Microsoft.NET.Test.Sdk` ni `xunit.runner.visualstudio` ne sont nécessaires. `coverlet.MTP` `10.1.0` produit le Cobertura (`--coverlet --coverlet-output-format cobertura`, restreint à `[OmniEurope.Blazor]*`) et `Microsoft.Testing.Extensions.TrxReport` `2.5.2` le TRX (`--report-trx`).
- les packages MAUI sont en `11.0.10`, dernière version stable publiée (`11.0.0` était la première). L'hôte Windows `samples/OmniEurope.Blazor.HybridSmoke` cible `net11.0-windows10.0.19041.0` et son verrou est régénéré (la restauration exige `-p:DesignTimeBuild=true` sans le workload, `NETSDK1147` sinon), mais il n'a pas pu être compilé ni exécuté le 2026-11-11 : le SDK `11.0.100` y exige le workload `maui-tizen`, absent du poste, et son installation demande une élévation. Le blocage de `10.0.120` (`CS0618` dans `XamlTypeInfo.g.cs`) n'a pas été rejoué sous .NET 11. Tant qu'un poste doté du workload n'a pas rejoué `eng/Test-HybridHost.ps1`, l'hôte Hybrid est non vérifié sous .NET 11.
- `Microsoft.CodeAnalysis.CSharp` est en `5.9.0`, dernière version publiée sur NuGet.org. Le compilateur du SDK `11.0.100` est `5.12.0`, non publié : un analyseur ne peut pas référencer un compilateur plus récent que celui du SDK qui le charge (`CS9057`), et un projet qui référence ce dépôt par `ProjectReference` charge les analyseurs avec son propre SDK ; `5.9.0` est chargé par tout SDK `11.0`. Un test de convention fige cette version contre le plancher. La version passe au compilateur du plancher dès que celui-ci est publié. Seul l'analyseur `OE0001` livré dans le paquet déroge : il référence `5.0.0` (`VersionOverride`), la Roslyn du SDK `10.0.100`, pour que tout SDK .NET 10 le charge ; `eng/Test-Package.ps1` refuse un analyseur livré qui référence une Roslyn plus récente.
- le SDK a un plancher unique dans `global.json` (`version: 11.0.100`, `rollForward: latestFeature`) : toute bande `11.0` à partir de `11.0.100` convient (ADR-002). Aucun workload set n'est figé : seul le job MAUI installe `maui-windows`, et `eng/Test-SdkBand.ps1` vérifie le plancher dans les deux jobs plutôt que de recopier un numéro dans les workflows. Les hôtes WebAssembly reçoivent du SDK trois paquets implicites à la version de son runtime (`Microsoft.NET.ILLink.Tasks`, `Microsoft.NET.Sdk.WebAssembly.Pack`, `Microsoft.AspNetCore.App.Internal.Assets`) ; `Directory.Build.targets` les épingle sur `OmniImplicitSdkPackVersion`, alignée sur les paquets `Microsoft.AspNetCore.*`, pour que les verrous se restaurent en `--locked-mode` sous toute bande (sans ce pin, `NU1004` sous `10.0.202` et `10.0.303`, constaté sous .NET 10). La restauration verrouillée se fait en Release : en Debug, un SDK `10.0.1xx` ou `10.0.2xx` (constat .NET 10) injecte aussi `Microsoft.DotNet.HotReload.WebAssembly.Browser` à sa propre version, impossible à épingler. Le pack d'exécution Mono des hôtes WebAssembly (`Microsoft.NETCore.App.Runtime.Mono.browser-wasm`, d'où viennent les bibliothèques natives de `dotnet.native.wasm`) suit la même version : un workload `wasm-tools` installé le ramènerait au runtime qu'il embarque (`10.0.13` sous le manifeste `10.0.113`, constat .NET 10), sans le correctif Brotli de `10.0.14` (GHSA-p3jp-9v83-76w9, corrigé aussi dans `11.0.0`) ; la cible `OmniPinMonoRuntimePack` le remet sur `OmniImplicitSdkPackVersion` (le pack manquant se restaure depuis NuGet, il n'entre pas dans les verrous) et `eng/Test-WasmRuntimeVersion.ps1 -PublishPath <dossier>` échoue quand un `dotnet.native.wasm` publié porte une autre version. `eng/Test-WasmRuntimeVersionFixtures.ps1` est l'auto-test de cette garde (publication conforme acceptée ; runtime plus ancien, runtime absent et script d'une autre version rejetés), lancé en CI juste avant elle.

## Application vitrine

La vitrine (`site/`) est une application déployée qui ne fait pas partie du paquet NuGet : ses projets ne sont pas empaquetables et ses dépendances n'entrent pas dans celles de la bibliothèque. Relevé du 27 octobre 2026, dernières versions stables publiées par NuGet.org :

- l'API `OmniEurope.Blazor.Showcase.Back` utilise `Npgsql.EntityFrameworkCore.PostgreSQL` `10.0.3` (PostgreSQL est le seul fournisseur ; aucune version stable 11 n'existe le 2026-11-11, seulement `11.0.0-rc.3`, donc toute la pile EF Core reste en 10), `Microsoft.Extensions.Diagnostics.HealthChecks.EntityFrameworkCore` `10.0.15` pour `/health/ready` et `Microsoft.EntityFrameworkCore.Design` `10.0.15`, réservé à la génération des migrations (`PrivateAssets=all`, absent de la publication);
- `tests/OmniEurope.Blazor.Showcase.Back.Tests` utilise `Microsoft.AspNetCore.Mvc.Testing` `11.0.0` et `Testcontainers.PostgreSql` `4.16.0`, qui démarre un vrai PostgreSQL `postgres:18-alpine` dans Docker;
- la base de développement locale est l'image `postgres:18-alpine` de `deploy/compose/dev-db.compose.yml`;
- l'image PostgreSQL est épinglée par digest, relevé du 1er novembre 2026, dans le bloc `images` de `eng/dependency-policy.json`. `eng/Test-DependencyPolicy.ps1` refuse toute image des tests, de `deploy/` ou des workflows qui n'y figure pas à l'identique. Dependabot ne suit pas cette image : une mise à jour se fait à la main, dans la politique et ses deux usages, avec le digest relu sur le registre.
## Ressources tierces hors NuGet

Les ressources recopiées dans le dépôt sont déclarées dans `eng/vendored-assets.json`, qui pilote leur section dans `NOTICE.md`, leur composant CycloneDX et la conservation de leur texte de licence. Y figurent aujourd'hui cinq ressources : Phosphor Icons `2.1.1` (MIT), source des tracés intégrés d'`OmniIcon`, et les quatre polices web variables du catalogue `OmniThemeFonts` servies par le paquet (sous-ensemble latin, Fontsource `5.3.0`, OFL-1.1) : Inter, Lexend, Source Serif 4 et JetBrains Mono. Toute mise à jour doit rejouer `eng/Generate-Sbom.ps1` puis `eng/Test-Sbom.ps1`.

Toute modification doit mettre à jour les verrous, passer les tests et conserver les contrôles de couverture, de SBOM et de licences.
