# Matrice de compatibilité

| Hôte | Cible | Niveau | Contraintes |
|---|---|---|---|
| Blazor Server / Interactive Server | .NET 10 | Compilation, fumée HTTP et contrôles navigateur vérifiés | Le catalogue répond, expose ses assets et son en-tête CSP ; le dialogue et son focus, le rôle de la notification et la sélection de l'éditeur sont exercés dans Chromium (`eng/Test-CatalogProbe.mjs`), console sans erreur et sans violation CSP. |
| Blazor WebAssembly | .NET 10 | Compilation, publication et interaction navigateur vérifiées | La sonde sert l'artefact avec ses en-têtes de déploiement, démarre Chromium, clique `#wasm-action`, constate le compteur et la progression à 1, puis exige une console sans erreur et une CSP stricte. |
| Blazor Web App Interactive Auto | .NET 10 | Prérendu, hydratation et interaction vérifiés | La sonde publiée attend l'interactivité, clique `#auto-action`, constate le compteur à 1 et exige une console sans erreur via CDP. |
| MAUI Blazor Hybrid | .NET 10 / MAUI 10.0.101 | Compilation et exécution WebView2 vérifiées | L'application Windows minimale charge `HybridSmoke` dans `BlazorWebView` ; lancée avec `HYBRIDSMOKE_SELFTEST`, elle s'auto-teste dans sa propre WebView2 (clic sur `#hybrid-action`, compteur à 1, langue, titre et erreurs de console relevés) et publie le résultat sur sa sortie standard, que `eng/Test-HybridHost.ps1` lit et vérifie. |

La bibliothèque dépend de trois paquets compatibles avec le client, `Microsoft.AspNetCore.Components.Web`, `Microsoft.Extensions.Localization` et `HtmlSanitizer` (assainissement du HTML de l'éditeur), n'accède pas directement au DOM depuis C# et délègue les comportements navigateur (focus, grille, superpositions, éditeurs, etc.) à des modules JavaScript statiques servis par le paquet, couverts par le scan CSP ; voir [csp-contract.md](contracts/csp-contract.md). Les dates reposent sur `DateOnly` ou `DateTimeOffset`. Le scheduler accepte un `TimeZoneInfo`; si le consommateur ne le fournit pas, il utilise `TimeZoneInfo.Local`, donc le fuseau dépend implicitement de l'hôte. Fournir le paramètre explicitement est nécessaire pour un résultat reproductible.

Le rendu statique côté serveur, sans mode interactif, n'est pas un hôte pris en charge pour les comportements qui passent par ces modules ni pour le chargement distant d'`OmniDataGrid` : une grille alimentée par `Load` envoie sa première requête au premier rendu interactif, donc un prérendu ou une page statique la montre en chargement, sans ligne (`DataGridInitialLoadTests.StaticRender_ShowsTheLoadingState_AndSendsNoRequest`).

Le catalogue local constitue l'hôte Server de référence avec contrôles HTTP et navigateur. WebAssembly est publié puis exercé de façon autonome par `eng/Test-WasmHost.ps1`, avec en-têtes, assets, clic, progression, console et CSP vérifiés. Interactive Auto est exercé dans Chromium après hydratation. Hybrid est construit et exécuté comme application MAUI Windows dans WebView2, dont l'auto-test publie son verdict sur la sortie standard. Les scripts échouent si l'interaction attendue n'aboutit pas ou si la console contient une erreur.
