# Matrice de compatibilité

| Hôte | Cible | Niveau | Contraintes |
|---|---|---|---|
| Blazor Server / Interactive Server | .NET 11 | Compilation et tests vérifiés sous .NET 11 ; fumée HTTP et contrôles navigateur vérifiés sous .NET 10, non rejoués sous .NET 11 | Le catalogue répond, expose ses assets et son en-tête CSP ; le dialogue et son focus, le rôle de la notification et la sélection de l'éditeur sont exercés dans Chromium (`eng/Test-CatalogProbe.mjs`), console sans erreur et sans violation CSP. |
| Blazor WebAssembly | .NET 11 | Compilation et tests vérifiés sous .NET 11 ; publication et interaction navigateur vérifiées sous .NET 10, non rejouées sous .NET 11 | La sonde sert l'artefact avec ses en-têtes de déploiement, démarre Chromium, clique `#wasm-action`, constate le compteur et la progression à 1, puis exige une console sans erreur et une CSP stricte. |
| Blazor Web App Interactive Auto | .NET 11 | Compilation et tests vérifiés sous .NET 11 ; prérendu, hydratation et interaction vérifiés sous .NET 10, non rejoués sous .NET 11 | La sonde publiée attend l'interactivité, clique `#auto-action`, constate le compteur à 1 et exige une console sans erreur via CDP. |
| MAUI Blazor Hybrid | .NET 11 / MAUI 11.0.10 | Non vérifié sous .NET 11 (compilation impossible sur le poste du 2026-11-11 : workload `maui-tizen` du SDK 11 absent) ; compilation et exécution WebView2 vérifiées sous .NET 10 / MAUI 10.0.101 | L'application Windows minimale charge `HybridSmoke` dans `BlazorWebView` ; lancée avec `HYBRIDSMOKE_SELFTEST`, elle s'auto-teste dans sa propre WebView2 (clic sur `#hybrid-action`, compteur à 1, langue, titre et erreurs de console relevés) et publie le résultat sur sa sortie standard, que `eng/Test-HybridHost.ps1` lit et vérifie. |

Le paquet cible `net10.0` et `net11.0` (décision de l'utilisateur du 2026-11-11 ; `net9.0` n'est plus livré) : un hôte .NET 10 reçoit `lib/net10.0`, compilé contre `Microsoft.AspNetCore.Components.Web` et `Microsoft.Extensions.Localization` `10.0.15`, un hôte .NET 11 reçoit `lib/net11.0`, compilé contre ces paquets en `11.0.0`. La surface publique est la même sur les deux cibles (`eng/Test-PublicApi.ps1` compare chacune à `docs/public-api.txt`). La suite `tests/OmniEurope.Blazor.Tests` s'exécute sur les deux cibles ; sur `net10.0` elle laisse de côté les tests de la vitrine (application `net11.0`) et valide les formulaires par `EditContext.Validate`, seule entrée de validation de .NET 10. Les hôtes de fumée du tableau ci-dessus sont des applications .NET 11 : aucun hôte .NET 10 n'exerce `lib/net10.0` dans un navigateur, qui n'est donc vérifié que par la suite bUnit sur le runtime .NET 10.

La bibliothèque dépend de trois paquets compatibles avec le client, `Microsoft.AspNetCore.Components.Web`, `Microsoft.Extensions.Localization` et `HtmlSanitizer` (assainissement du HTML de l'éditeur), n'accède pas directement au DOM depuis C# et délègue les comportements navigateur (focus, grille, superpositions, éditeurs, etc.) à des modules JavaScript statiques servis par le paquet, couverts par le scan CSP ; voir [csp-contract.md](contracts/csp-contract.md). Les dates reposent sur `DateOnly` ou `DateTimeOffset`. Le scheduler accepte un `TimeZoneInfo`; si le consommateur ne le fournit pas, il utilise `TimeZoneInfo.Local`, donc le fuseau dépend implicitement de l'hôte. Fournir le paramètre explicitement est nécessaire pour un résultat reproductible.

Le rendu statique côté serveur, sans mode interactif, n'est pas un hôte pris en charge pour les comportements qui passent par ces modules ni pour le chargement distant d'`OmniDataGrid` : une grille alimentée par `Load` envoie sa première requête au premier rendu interactif, donc un prérendu ou une page statique la montre en chargement, sans ligne (`DataGridInitialLoadTests.StaticRender_ShowsTheLoadingState_AndSendsNoRequest`).

Le catalogue local constitue l'hôte Server de référence avec contrôles HTTP et navigateur. WebAssembly est publié puis exercé de façon autonome par `eng/Test-WasmHost.ps1`, avec en-têtes, assets, clic, progression, console et CSP vérifiés. Interactive Auto est exercé dans Chromium après hydratation. Hybrid est construit et exécuté comme application MAUI Windows dans WebView2, dont l'auto-test publie son verdict sur la sortie standard. Les scripts échouent si l'interaction attendue n'aboutit pas ou si la console contient une erreur.
