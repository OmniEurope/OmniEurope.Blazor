# deploy

Deployment files of the showcase application (`site/`), never of the NuGet package.

| File | Role |
| --- | --- |
| `compose/dev-db.compose.yml` | Local development PostgreSQL, started by the local launcher. Not a deployment file. |
| `compose/remote.compose.yml` | Production and QA stack: front, API, PostgreSQL. The file the pipeline setup wizard selects (its name says `remote`, no development word). |
| `docker/Dockerfile.front` | Publishes the WebAssembly showcase (locked restore, fingerprinted assets) and serves it with `StaticServer.Program.cs`. |
| `docker/StaticServer.Program.cs` | Static host of the front: every rule of the published `wwwroot/_headers` (CSP included), the API origin added to `connect-src`, `appsettings.json` written from `API_BASE_URL`, and the cache policy of every response. |
| `docker/Dockerfile.back` | Publishes the showcase API (locked restore); it applies its EF migrations itself at start-up. |

## Deployment pipelines (project prefix `oe`)

`remote.compose.yml` follows the contract of the production deployment pipelines: no value and no
secret in the file, every variable comes from the libraries `oe.share`, `oe.prod`, `oe.qa` and the vault.
The strategy is `replace` (`PORT_FRONT`, `PORT_BACK`); pick it in the setup wizard, the file declares no
blue and green ports.

| Variable | Provided by |
| --- | --- |
| `APP_VERSION`, `FRONT_URL`, `API_BASE_URL`, `DOTNET_SDK_VERSION` | the deployment itself (release, public addresses, `global.json`) |
| `PORT_FRONT`, `PORT_BACK` | the port registry of the chosen server |
| `APPNAME`, `ENV`, `DB_USER` | conventions written by the wizard into the library (`oe`, `prod` or `qa`) |
| `DB_PASSWORD` | generated by the wizard into the vault |

The API (`site/OmniEurope.Blazor.Showcase.Back`) reads `ConnectionStrings__DefaultConnection`,
`Cors__Origins__0` (the front's origin, no path, no trailing slash) and `ForwardedHeaders__Enabled`; the compose
file sets them. Its health probes are `/health/live` and `/health/ready` (PostgreSQL included).

## Local proof of the stack

```text
docker compose -p oe-proof --env-file <untracked env file> -f deploy/compose/remote.compose.yml build
docker compose -p oe-proof --env-file <untracked env file> -f deploy/compose/remote.compose.yml up -d --wait
docker compose -p oe-proof --env-file <untracked env file> -f deploy/compose/remote.compose.yml down -v
```

The env file holds the ten variables above (for example `PORT_FRONT=18080`, `PORT_BACK=18081`,
`API_BASE_URL=http://127.0.0.1:18081/`, `FRONT_URL=http://127.0.0.1:18080`); keep it outside the repository.
